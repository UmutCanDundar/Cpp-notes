# `decltype(e)` vs `decltype((e))` Cheat Sheet

What `decltype` yields for variables, objects, member access, function calls, operators and lambdas, with and without the extra parentheses.

All results were produced with g++ 13.3 (`-std=c++17`; the lambda rows need `-std=c++20`, because a lambda-expression is not allowed in an unevaluated operand before C++20).

---

## The two rules

`decltype(e)` works in one of two modes:

1. **`e` is an unparenthesized id-expression or an unparenthesized class member access** (`x`, `n.x`, `Nec::y`) → the result is the **declared type** of the entity.
2. **Anything else** (including a parenthesized name) → the result depends on the **value category** of the expression. With `T` being the expression's type:

| Value category | Result |
|---|---|
| prvalue | `T` |
| lvalue | `T&` |
| xvalue | `T&&` |

The extra parentheses in `decltype((e))` switch off rule 1 and force rule 2.

---

## Setup

```cpp
struct Nec { int x; int& r; static int y; };

int a{};
Nec n{1, a};
const Nec cn{1, a};

int i = 0; const int ci = 0; int& ref = i; int&& rr = 5;
int* ptr = &i; int arr[3];

int f(int);
auto l = [](int v) { return v; };
```

In the tables, **`decltype(e)`** and **`decltype((e))`** are the two forms for the same expression `e`.

---

## 1. Plain variables

| Expression | Category | `decltype(e)` | `decltype((e))` |
|---|---|---|---|
| `i` | lvalue | `int` | `int&` |
| `ci` | lvalue | `const int` | `const int&` |
| `ref` | lvalue | `int&` | `int&` |
| `rr` | lvalue | `int&&` | `int&` |
| `ptr` | lvalue | `int*` | `int*&` |
| `arr` | lvalue | `int[3]` | `int(&)[3]` |

`rr` is declared `int&&`, but as an expression it is a name, hence an lvalue.

## 2. The object itself

| Expression | Category | `decltype(e)` | `decltype((e))` |
|---|---|---|---|
| `n` (lvalue) | lvalue | `Nec` | `Nec&` |
| `Nec{1,a}` (temporary) | prvalue | `Nec` | `Nec` |
| `move(n)` | xvalue | `Nec&&` | `Nec&&` |

## 3. Member access

| Expression | Category | `decltype(e)` | `decltype((e))` |
|---|---|---|---|
| `n.x` | lvalue | `int` | `int&` |
| `n.r` | lvalue | `int&` | `int&` |
| `n.y` (static) | lvalue | `int` | `int&` |
| `cn.x` (const object) | lvalue | `int` | `const int&` |
| `Nec{1,a}.x` | xvalue | `int` | `int&&` |
| `Nec{1,a}.r` | lvalue | `int&` | `int&` |
| `Nec{1,a}.y` | lvalue | `int` | `int&` |
| `move(n).x` | xvalue | `int` | `int&&` |
| `move(n).r` | lvalue | `int&` | `int&` |
| `move(n).y` | lvalue | `int` | `int&` |

How the category of a member access `E1.E2` is decided:

| Member kind | Result |
|---|---|
| Reference member (`r`) | **always lvalue**, whatever `E1` is |
| Static member (`y`) | **always lvalue**, independent of `E1` |
| Non-static member (`x`) | lvalue if `E1` is an lvalue, otherwise **xvalue** |

The `const` of the object shows up only in the parenthesized form (`cn.x` → `const int&`), because `decltype(cn.x)` reports the declared type `int`.

## 4. Functions

| Expression | Category | `decltype(e)` | `decltype((e))` |
|---|---|---|---|
| `f` (the name) | lvalue | `int(int)` | `int(&)(int)` |
| `f(1)` (call) | prvalue | `int` | `int` |
| `&f` | prvalue | `int(*)(int)` | `int(*)(int)` |

A call expression yields its return type: `int` → prvalue (`int`), `int&` → lvalue (`int&`), `int&&` → xvalue (`int&&`). Parentheses make no difference.

## 5. Operators

| Expression | Category | `decltype(e)` | `decltype((e))` |
|---|---|---|---|
| `i + 3` | prvalue | `int` | `int` |

Other operators follow the same logic (look at the category of the result): `++i` and `i = 5` are lvalues (`int&`), `i++` is a prvalue (`int`), `*ptr` is an lvalue (`int&`), `&i` is a prvalue (`int*`).

## 6. Lambdas

| Expression | Category | `decltype(e)` | `decltype((e))` |
|---|---|---|---|
| `l` (lambda variable) | lvalue | closure type | closure type`&` |
| `l(1)` (call) | prvalue | `int` | `int` |
| `[](int v){ return v; }` (lambda expression) | prvalue | closure type | closure type |

The closure type is an unnamed class generated by the compiler (g++ prints it as `main()::<lambda(int)>`), so it cannot be spelled out by hand.
